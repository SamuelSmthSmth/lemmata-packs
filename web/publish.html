Publish a pack

A pack is a module's results, or a topic's, written as proofs the checker can read. You make it in the app, and a pull request puts it here. Nothing is listed until every entry checks.

1. Make it in the app

  1. Open Lemmata and put your proofs in one folder (the Files tab).
  2. Click the folder's pack button, or Library → New pack…, and fill in the details:
    • Name: scope/slug, lower case, such as yourname/real-analysis. The scope is yours: your name, a society, a department. core/ is kept for the packs that ship with the app.
    • Version: 1.0.0 to start. Raise it whenever you change the pack, so installed copies are offered the update.
    • Course codes are optional: a pack can be a topic.
    • For each proof, a reference in the notes' own numbering (Example 2.18), a title and a chapter. Mark a deliberate mistake as a trap and say what is wrong.
  3. Export .pack.json. The app checks every proof as it exports and records the verdict each gives, so the file is true when it leaves your hands.

2. Open a pull request

  1. Add the file to the registry repository at packs/<scope>/<slug>.pack.json, matching its name. GitHub's Add file → Upload files works; nothing needs installing.
  2. Open the pull request. The registry's checks run at once: the pack must be valid, and every entry must give its recorded verdict under the engine the app runs today. Fix whatever they report and push again.
  3. Once it is merged, the pack is listed here within minutes, and anyone can find it from the app's Library.

What gets merged

Your own wording
Restate results in your words and write your own proofs. Never paste lecture notes or textbook passages.
Entries that check
A proof must check; a trap must fail, with an explanation of the mistake.
The source's numbering
References follow the notes' own numbers, so students can find their way back.
An open licence
Packs are CC BY-SA 4.0 unless the pack names another licence.

Writing one by hand

A pack is a JSON file: a name, a version, chapters and entries, each entry with its source and the verdict it must give. The registry's example pack shows the format, and every file is checked against it.
